# Milestone 3.1: Basic Text-to-Speech (TTS)

## 1. Goal

Milestone 3.1 extends the voice pipeline by introducing conversational speech output (Text-to-Speech). Spoken or typed requests processed by the Agent Orchestrator now culminate in audible vocalization of the assistant's response.

**Complete End-to-End Flow:**

```
User Spoken Voice
        ↓
Microphone Capture (Web Audio API)
        ↓
Silero VAD (Speech Segment Detection)
        ↓
STT (Speech-to-Text via Gemini / Mock STT)
        ↓
Transcript String
        ↓
Existing Agent Orchestrator (Intent Extraction & Temporal Reasoning)
        ↓
Calendar Operation (Google Calendar OAuth / MockCalendarService)
        ↓
Assistant Response Message
        ↓
Text-To-Speech (TTS)
        ↓
Audio Speaker (User hears the response)
```

## 3. Provider Abstraction (`ITextToSpeechProvider`)

The Agent and UI do not depend directly on any specific vendor or speech engine. The interface contract is defined in `src/renderer/src/services/tts/ITextToSpeechProvider.ts`:

```typescript
export interface ITextToSpeechProvider {
  readonly id: string
  readonly name: string
  isAvailable(): Promise<boolean>
  getVoices(): Promise<TTSVoice[]>
  speak(text: string, options?: SpeakOptions): Promise<void>
  stop(): void
  isSpeaking(): boolean
}
```

This abstraction allows future cloud-based or neural TTS providers (e.g. Google Cloud TTS, Gemini Audio, or ElevenLabs) to be plugged in during later milestones without modifying business logic.

---

## 4. Selected Initial Provider

- **Primary Provider**: `WebSpeechTtsProvider` using Chromium's native `window.speechSynthesis` (Web Speech API).
- **Rationale**:
  - Native to Chromium/Electron: requires **zero additional dependencies** and no native binary compilations.
  - Zero external cloud latency: speech synthesis executes locally on the user's workstation.
  - Zero API keys required: maintains strict security boundaries.
  - Native OS integration: automatically utilizes Windows SAPI / OneCore voices (e.g. Microsoft HoaiMy, Microsoft An), macOS system voices (e.g. Linh), and Linux `speech-dispatcher`.
- **Offline / Headless Testing**: `MockTtsProvider` provides deterministic voice synthesis simulation and history recording for automated CI/unit tests.

## 5. Vietnamese Voice Selection Algorithm

As mandated by Section 5, Vietnamese is the primary language. `selectVietnameseVoice` in `speechFormatter.ts` implements this resolution order:

1. **Priority 1 (Exact match)**: Search for a voice where `lang` equals `"vi-VN"` (or `"vi_VN"`, case-insensitive).
2. **Priority 2 (Partial prefix match)**: If unavailable, search for any voice whose `lang` starts with `"vi"`.
3. **Priority 3 (Platform default fallback)**: If no Vietnamese voice is installed on the host operating system, select the system's default voice and surface an informative warning banner:
   > _"Hệ thống chưa có giọng tiếng Việt (vi-VN). Đang dùng giọng mặc định: [Voice Name] ([lang])."_

## 6. Agent Result → TTS Speech Formatting

Raw agent results contain formatted markdown, bullet points, and date-time strings. To produce natural spoken cadence:

| Raw Agent Response                                                                                                                 | Cleaned Spoken Utterance                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Bạn có 2 sự kiện được lên lịch:`<br>`• Họp nhóm (09:00 - 10:00, ngày 03/10/2026)`<br>`• Ăn trưa (12:00 - 13:00, ngày 03/10/2026)` | `Bạn có 2 sự kiện được lên lịch: Họp nhóm (09:00 đến 10:00, ngày 03/10/2026), Ăn trưa (12:00 đến 13:00, ngày 03/10/2026)` |
| `Đã lên lịch thành công: "Họp với A" (15:00 - 16:00, ngày 03/10/2026)`                                                             | `Đã lên lịch thành công: Họp với A (15:00 đến 16:00, ngày 03/10/2026)`                                                    |
| `Đã cập nhật sự kiện "Họp với A" sang thời gian mới: 16:00 - 17:00, ngày 03/10/2026`                                               | `Đã cập nhật sự kiện Họp với A sang thời gian mới: 16:00 đến 17:00, ngày 03/10/2026`                                      |

- Bullet points (`•`) are removed and replaced with conversational commas/pauses.
- Hyphens in time expressions (`15:00 - 16:00`) are translated to `"đến"` so the voice synthesizer does not pronounce them as minus signs or hyphens.
- Quotes and markdown syntax (`*`, `_`, `#`) are stripped.
- Empty or whitespace-only messages are discarded (no-op).

## 7. Text + Voice Output Parity

Both textual and voice representations are preserved simultaneously:

1. **On Screen**:
   - `ChatFeed` displays user query and assistant response cards.
   - `TranscriptionDisplay` displays user transcript, intent badge, and response message.
2. **Audio Speakers**:
   - TTS synthesizes and plays the formatted message aloud.

---

## 8. State Machine & Distinguishing User vs Assistant Speech

Milestone 3.1 cleanly isolates user speech detection from assistant speech synthesis:

```
[User Mic]  ──> VAD detected ──────> state: 'speaking' (User is speaking)
[User Mic]  ──> Speech ended ──────> state: 'transcribing' (STT)
[Agent]     ──> Processing   ──────> state: 'processing' (Agent Orchestrator)
[TTS]       ──> Speech play  ──────> state: 'speaking-assistant' (Assistant TTS)
[TTS]       ──> Playback end ──────> state: 'success' ──(cooldown)──> 'listening'
```

---

## 9. Prevention of TTS → Microphone Feedback Loop

To prevent the assistant's speech from being picked up by the microphone and re-triggering an infinite loop (`TTS → Microphone → VAD → STT → Agent → TTS`):

1. **`isAssistantSpeakingRef` Lock**:
   - While `TextToSpeechService` is active, `isAssistantSpeakingRef.current` is set to `true`.
   - In `onSpeechStart`: If `isAssistantSpeaking` is active, speech start is dropped.
   - In `onSpeechEnd`: If `isAssistantSpeaking` is active, the audio segment is dropped without routing to STT or Agent.
2. **Reverberation Cooldown Buffer (`assistantCooldownUntilRef`)**:
   - When assistant TTS finishes speaking, a 400ms cooldown window is enforced.
   - Any room reverberation, speaker echo, or tail audio within this 400ms window is discarded before VAD resumes listening for new user speech.

---

## 10. Stop / Cancel Behavior

- `TextToSpeechService.stop()` immediately cancels any active speech via `window.speechSynthesis.cancel()`.
- UI provides a visible `[⏹ Dừng đọc]` button while speech is playing.
- When the user starts a new voice command, clicks "Stop Listening", or unmounts the component, all audio playback is cleanly aborted.

---

## 11. Security Boundary

- Native Web Speech API does not require or touch API keys or cloud tokens.
- Google OAuth credentials, refresh tokens, and Gemini API keys remain strictly confined to the Electron Main process.
- No sensitive internal details or token strings are sent to the speech synthesizer.

## 14. Known Limitations & What is Intentionally Deferred to M4

As strictly defined by the Milestone 3.1 specification:

- ❌ **Streaming TTS / Sentence-level streaming**: The assistant vocalizes the complete response message. Streaming TTS chunking is deferred to M4.
- ❌ **Barge-in / Live Echo Cancellation**: Acoustic echo cancellation is handled via software state suppression. Hardware AEC and barge-in interruption are deferred.
- ❌ **Wake Word**: Microphone listening is activated via the UI control ("Start Listening"). Wake word ("Hey Assistant") is deferred.
- ❌ **Voice Cloning / Custom Neural Models**: Native system voices are used.
