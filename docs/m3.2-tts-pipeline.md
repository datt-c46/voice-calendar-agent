# Milestone 3.2: Advanced TTS Pipeline Preparation

## 1. Goal

Milestone 3.2 upgrades the Text-to-Speech (TTS) architecture from single-utterance synthesis (introduced in M3.1) into a modular, sequential queue pipeline. This refactoring prepares the assistant for Milestone 4 (Streaming + Latency Optimization) by establishing clean boundaries between response formatting, sentence segmentation, sequential queue scheduling, and audio playback.

> [!IMPORTANT]
> **M3.2 is NOT streaming TTS.** There is no audio chunk streaming, token streaming, WebSocket/WebRTC, or PCM stream playback in this milestone. Synthesis and playback execute cleanly one complete sentence at a time via a sequential FIFO queue.

```
Agent
  ↓
Assistant Response
  ↓
Formatter
  ↓
Sentence Splitter
  ↓
TTS Queue
  ↓
TTS Provider
  ↓
Speaker
```

---

## 2. Existing M3.1 Architecture

In M3.1, the TTS implementation directly received the raw string response from the Agent Orchestrator:

```
[Agent Result]
      │
      ▼
[formatAgentResponseForSpeech()]
      │
      ▼
[TextToSpeechService.speak(entireText)]
      │
      ▼
[WebSpeechTtsProvider.speak(entireText)]  <--- Single utterance to window.speechSynthesis
      │
      ▼
[Speaker Output]
```

### Limitations of M3.1:

1. **Monolithic Utterances**: Long multi-sentence responses (such as listing multiple calendar events) were passed as one large monolithic utterance to `speechSynthesis`. If a user stopped playback midway or triggered a new request, there was no granular sentence tracking.
2. **Coupled Formatting**: UI text and TTS text were not systematically separated into dedicated fields; conversational pauses and bullet conversions were done as an ad-hoc regex pass over the single output string.
3. **No Sentence Boundaries**: Native browser synthesis of very long single-block strings can exhibit uneven cadence, lack of natural pause control, or platform-dependent buffer timeouts.
4. **Race Conditions on Quick Updates**: Rapid sequential commands could lead to overlapping speech or stale completion callbacks.

---

## 3. New M3.2 Architecture

M3.2 refactors the TTS flow into discrete, single-responsibility layers:

```
+-----------------------------------------------------------------------------------+
|                              RENDERER PROCESS                                     |
|                                                                                   |
|  [Agent Orchestrator / Command Result]                                            |
|          │                                                                        |
|          ▼                                                                        |
|  1. [Response Formatter] (responseFormatter.ts)                                   |
|     ├── Generates visual `uiText` (bullet points, clear structure)                |
|     ├── Generates conversational `ttsText` (spoken pauses, text normalization)   |
|     └── Normalizes markdown, quotes, whitespace, and range hyphens                |
|          │                                                                        |
|          ▼                                                                        |
|  2. [Sentence Splitter] (sentenceSplitter.ts)                                     |
|     ├── Protects decimals ("3.5 giờ"), times ("15:30"), abbreviations ("TP.")     |
|     ├── Splits on Vietnamese & English punctuation (. ? ! … \n)                   |
|     └── Produces: `string[]` (clean, non-empty sentence chunks)                   |
|          │                                                                        |
|          ▼                                                                        |
|  3. [TTS Queue] (ttsQueue.ts)                                                     |
|     ├── FIFO queue of sentences with sequential processing                        |
|     ├── Generation token guard (`currentGeneration` counter)                      |
|     ├── Progress tracking (`currentIndex`, `totalSentences`, `queueLength`)       |
|     └── Preemption: new request cancels old generation immediately                |
|          │                                                                        |
|          ▼                                                                        |
|  4. [TTS Service] (ttsService.ts)                                                 |
|     ├── State machine: `idle` | `queued` | `speaking` | `completed` | `cancelled` |
|     ├── Feedback suppression: `isAssistantSpeaking = true` + 400ms cooldown       |
|     └── Vietnamese voice selector (`vi-VN` -> `vi*` -> platform default)          |
|          │                                                                        |
|          ▼                                                                        |
|  5. [ITextToSpeechProvider] (Audio Playback Abstraction)                          |
|     ├── [WebSpeechTtsProvider] (Native `window.speechSynthesis`)                  |
|     └── [MockTtsProvider]      (Automated Unit & Integration Tests)               |
|          │                                                                        |
|          ▼                                                                        |
|  6. [Speaker] (User hears sentence 1, then sentence 2, then sentence 3...)       |
|                                                                                   |
|  [UI Progress Indicator]                                                          |
|  "🔊 Đang đọc (1/3)..." | [⏹ Dừng đọc] | [🔊 Nghe lại]                            |
+-----------------------------------------------------------------------------------+
```

## 4. Response Formatter (`responseFormatter.ts`)

The response formatter transforms raw Agent outputs into two distinct representations without requiring an LLM:

```typescript
export interface FormattedResponse {
  uiText: string
  ttsText: string
  sentences: string[]
}
```

### Deterministic Separation Rules:

- **UI Text**: Preserves list structure, bullet points (`• 09:00 - Họp nhóm`), and visual layout suitable for display in `TranscriptionDisplay`.
- **TTS Text**:
  - Replaces bullet points (`•`, `*`, `-`) with conversational pauses or numbered phrasing.
  - Converts time range dashes (`15:00 - 16:00` -> `15:00 đến 16:00`) for natural Vietnamese pronunciation.
  - Strips markdown formatting (`**bold**` -> `bold`, `*italic*` -> `italic`, `# Heading` -> `Heading`).
  - Cleans quotation marks and excess whitespace.
  - Never reads raw internal database IDs or ISO timestamps.

---

## 5. Sentence Segmentation (`sentenceSplitter.ts`)

Sentence segmentation divides normalized TTS text into discrete chunks while carefully protecting numerical, temporal, and abbreviated tokens:

### Protected Tokens (Token Masking):

1. **Decimal Numbers**: Protected via `(\d+)\.(\d+)` -> `3.5 giờ` does not split into `"3"` and `"5 giờ"`.
2. **Time Expressions**: Protected via `(\d{1,2}):(\d{2})` -> `15:30` remains intact.
3. **Common Abbreviations**: Protected list: `TP.`, `ThS.`, `TS.`, `BS.`, `GS.`, `v.v.`, `Mr.`, `Mrs.`, `Ms.`, `Dr.`, `vs.`, `e.g.`, `i.e.`.
4. **Ellipsis**: `...` or `…` treated as sentence terminators without creating dangling fragments.

### Boundary Detection:

- Chunks split on `(?<=[.?!…])\s+` and newline boundaries `[\r\n]+`.
- Empty or whitespace-only chunks are discarded.
- Single-sentence responses naturally yield an array of length 1.

## 6. TTS Queue (`ttsQueue.ts`)

The `TTSQueue` processes sentences sequentially in First-In-First-Out (FIFO) order:

```typescript
export class TTSQueue {
  enqueue(sentence: string): void
  enqueueMany(sentences: string[]): void
  async speak(text: string, options?: SpeakOptions): Promise<void>
  stop(): void
  clear(): void
  isSpeaking(): boolean
  getState(): TTSState
  getProgress(): TTSQueueProgress | null
  getMetrics(): TTSQueueMetrics | null
}
```

### Execution Flow:

1. `speak(text)` formats the text, splits it into sentences, increments the generation token, and begins sequential processing.
2. For each sentence:
   - Updates progress: `currentIndex = i`, `totalSentences = N`.
   - Calls `provider.speak(sentence, options)`.
   - Waits for playback completion before proceeding to sentence `i + 1`.
3. Emits state changes (`queued` -> `speaking` -> `completed`).

---

## 7. Playback Abstraction

Audio synthesis remains strictly encapsulated behind `ITextToSpeechProvider`:

```typescript
export interface ITextToSpeechProvider {
  readonly id: string
  readonly name: string
  isAvailable(): Promise<boolean>
  getVoices(): Promise<TTSVoice[]>
  speak(text: string, options?: SpeakOptions): Promise<void>
  stop(): void
  isSpeaking(): boolean
}
```

The queue interacts exclusively with `provider.speak(sentence)` and `provider.stop()`. This decouples the sentence segmentation and queue management from native browser APIs (`window.speechSynthesis`) or future neural streaming providers (M4).

## 8. Cancellation Behavior

To prevent the common speech synthesis bug where stopping sentence 1 causes an old `onend` callback to trigger sentence 2, `TTSQueue` utilizes a **Generation Token Guard**:

```typescript
private currentGeneration = 0

stop(): void {
  this.currentGeneration++ // Invalidate any running queue loops
  this.queue = []
  this.state = 'cancelled'
  this.provider.stop()
  if (this.activeResolve) {
    this.activeResolve()
    this.activeResolve = null
  }
}
```

### Guarantees:

- Active utterance is stopped immediately via `provider.stop()`.
- Unspoken queued sentences are purged immediately.
- Stale asynchronous completion callbacks compare their generation ID against `this.currentGeneration`; if mismatched, they abort without advancing the queue.
- In-flight `speak()` promises resolve cleanly without hanging.

---

## 9. Repeated Request Behavior

When a user submits request B while the assistant is still speaking response A:

1. The new call to `speak(requestB)` immediately invokes `this.stop()`.
2. The generation token is incremented, discarding all remaining sentences from request A.
3. Request B is formatted, split, and queued under the new generation token.
4. Sentences from request A and request B are never interleaved or mixed.

---

## 10. Feedback-Loop Prevention

To prevent acoustic feedback where the microphone hears the assistant's speech and triggers Silero VAD + STT into an infinite loop:

1. `TextToSpeechService` maintains `isAssistantSpeaking = true` throughout queue execution.
2. When the last sentence finishes (or on `stop()`), a **400ms acoustic decay cooldown** ensures room reverberation fades before `isAssistantSpeaking` resets to `false`.
3. In `useVoiceActivity.ts`, VAD frames detected while `isAssistantSpeaking === true` are suppressed from triggering speech start events.

---

## 11. Vietnamese Voice Handling

Preserved from M3.1 with exact fallback hierarchy:

1. Exact BCP-47 match: `vi-VN` (e.g., Microsoft An, Google Tiếng Việt, Apple Linh).
2. Generic prefix match: `vi*` (any Vietnamese locale voice).
3. Graceful fallback: System default voice if no Vietnamese voice is installed.
4. Voice selection is cached after discovery to prevent repeated enumeration overhead.

---

## 12. Error Handling

- **Empty / Whitespace Input**: `speak("")` returns immediately with status `'idle'` without enqueuing items or invoking the provider.
- **Provider Failure**: If `provider.speak()` rejects:
  - Error state `'error'` is recorded.
  - Remaining sentences in the queue are cancelled.
  - The error is logged to debug console and the speech promise rejects cleanly.
- **Voice Not Found**: Logs informative warning and falls back to platform default without crashing.

## 15. Known Limitations

- **Browser SpeechSynthesis Nuances**: The Web Speech API in Chromium can occasionally pause long utterances if backgrounded. The sentence segmentation in M3.2 mitigates this by keeping each utterance short.
- **Acoustic Echo Cancellation**: Handled via state guard (`isAssistantSpeaking` flag + cooldown) rather than DSP echo cancellation (DSP/AEC deferred to future audio stack optimizations).

---

## 16. What is Intentionally Deferred to M4

To keep Milestone 3.2 focused purely on pipeline preparation:

- ❌ **No Audio Chunk Streaming**: No streaming PCM, Web Audio buffers, or chunk-based audio streaming.
- ❌ **No Token-by-Token TTS**: TTS begins only after a complete sentence or complete Agent result is available.
- ❌ **No WebSockets / WebRTC / SSE**: Local desktop execution only.
- ❌ **No Barge-In / Interrupt via Wake Word**: Microphone remains gated during assistant speech.
- ❌ **No Conversation Memory**: Turn-by-turn memory is scheduled for subsequent milestones.
- ❌ **No Background / System Tray Mode**: Retains standard desktop window lifecycle.
