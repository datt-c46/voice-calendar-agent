# Milestone 2.4: Voice → Existing Agent Integration

## 1. Goal

Milestone 2.4 seamlessly bridges the voice capture & speech recognition pipeline from Milestone 2.3 into the existing calendar agent orchestrator established in Milestones 1 & 1.5.

**Core Pipeline:**

```
Microphone
    ↓
Audio Capture (Web Audio API)
    ↓
Silero VAD (Local ONNX)
    ↓
Speech Segment Finalized
    ↓
STT Provider (Gemini / Mock via IPC)
    ↓
Transcript String
    ↓
Existing Agent Orchestrator (Intent Extraction & Temporal Reasoning)
    ↓
Existing Calendar Service (Google Calendar / MockCalendarService)
    ↓
Result Displayed in UI (Transcript + Assistant Response)
```

Both manual text input (via `CommandInput`) and spoken voice input (via `MicrophoneControl` / `useVoiceActivity`) converge into the exact same Agent pipeline.

## 3. Voice → STT → Agent Flow

1. **User Speaks**: User presses "Bắt đầu nghe" (Start Listening). The VAD enters `'listening'` state.
2. **Speech Detected**: Silero VAD fires `onSpeechStart`, transitioning the state machine to `'speaking'`.
3. **Speech Ends**: VAD fires `onSpeechEnd(audioFloat32Array)`.
4. **WAV Encoding**: Audio is downsampled/formatted to standard 16kHz mono 16-bit PCM WAV.
5. **STT Invocation**: The WAV is sent via `window.api.stt.transcribe()` to the Electron Main process. State transitions to `'transcribing'`.
6. **STT Result**: The STT provider returns `{ text: "..." }`.
7. **Empty/Whitespace Guard**: If the recognized text is empty or blank, the pipeline halts immediately, shows `"Không nhận diện được nội dung."`, and returns to `'listening'`.
8. **Agent Execution**: State transitions to `'processing'`. The transcript string is forwarded directly into `handleSendCommand(text)` in `App.tsx`, triggering IPC `agent:execute-command`.
9. **Intent Extraction & Calendar Execution**: Inside the Main process, `AgentOrchestrator` extracts intent, normalizes dates to `Asia/Bangkok` (+07:00), and invokes the active calendar service (`GoogleCalendarService` or `MockCalendarService`).
10. **UI Render**: The result is returned to the renderer:
    - `TranscriptionDisplay` renders both user utterance and assistant reply with timing stats.
    - `ChatFeed` records the interaction with intent badge and formatted event previews.
    - `App.tsx` re-queries upcoming events to keep the calendar cards in sync.
11. **State Recovery**: After a short success/completion interval, VAD safely returns to `'listening'` so the user can issue subsequent commands hands-free.

## 4. IPC Architecture

No new or redundant IPC channels were added. The pipeline converges completely on established endpoints:

| Channel                 | Process         | Payload                            | Response               | Description                                            |
| ----------------------- | --------------- | ---------------------------------- | ---------------------- | ------------------------------------------------------ |
| `stt:transcribe`        | Renderer → Main | `{ base64, mimeType, durationMs }` | `STTResult`            | Transcribes recorded audio via Gemini or Mock STT      |
| `agent:execute-command` | Renderer → Main | `AgentCommandRequest` (`{ text }`) | `AgentCommandResponse` | Reused by both manual text input and voice transcripts |

**Security Boundary**: The renderer never touches Google tokens, client secrets, API keys, or raw external calendar endpoints.

| State          | Indicator         | Description                                  |
| -------------- | ----------------- | -------------------------------------------- |
| `idle`         | Gray badge        | Microphone and VAD inactive                  |
| `listening`    | Green badge       | Microphone active, listening for voice       |
| `speaking`     | Red pulsing badge | User is speaking, VAD buffering speech       |
| `transcribing` | Purple badge      | Transcribing speech via STT                  |
| `processing`   | Blue badge `⚡`   | Agent is executing intent & calendar command |
| `success`      | Emerald badge `✓` | Command completed successfully               |
| `error`        | Red badge `!`     | STT, Agent, or Calendar error encountered    |

## 6. Double Processing Prevention

Double processing is prevented via multiple synchronized layers:

1. **`isProcessingRef` Lock**:
   - `isProcessingRef.current` in `useVoiceActivity.ts` acts as an atomic lock.
   - If a new `onSpeechEnd` or React re-render occurs while `isProcessingRef.current === true`, the event is dropped.
2. **React Callback Stability**:
   - `onVoiceCommandRef.current` keeps the latest reference to `handleSendCommand` without needing to re-bind or restart the VAD instance on every component render.
3. **Discrete Segment Handling**:
   - Audio segments are only queued when VAD explicitly triggers `onSpeechEnd`. Misfires (`onVADMisfire`) discard audio immediately.

---

## 7. Empty & Invalid Transcript Handling

- If the STT provider returns an empty string `""`, whitespace only `"   "`, or undefined:
  - The transcript is **not** forwarded to the Agent.
  - A friendly notification is displayed: `"Không nhận diện được nội dung."`.
  - The pipeline immediately reverts to `'listening'`.
  - Zero calendar mutations or API calls occur.

---

## 8. Error Handling

Errors are compartmentalized into three distinct stages:

1. **STT Error**:
   - Caught in `useVoiceActivity` during `window.api.stt.transcribe`.
   - UI message: `"Không thể nhận diện giọng nói. Vui lòng thử lại."`.
2. **Agent Error**:
   - Generated when the extractor encounters unparseable phrasing or missing time parameters.
   - Sanitized message: `"Đã xảy ra lỗi khi xử lý yêu cầu..."` or `"Không thể hiểu lệnh..."`.
3. **Calendar / Network Error**:
   - If Google Calendar API returns a 4xx/5xx or network drops, `AgentOrchestrator` catches the exception and returns `success: false` with a clear explanation without leaking stack traces or credentials.

---

## 9. Timezone Regression Protection

All voice-scheduled events strictly adhere to the project's timezone policy established in M1.5:

- **Application Timezone**: `Asia/Bangkok` (`UTC+7`).
- When a user says:
  > _"Chiều mai lúc 3 giờ họp với A"_
- The extracted event start time is:
  `2026-10-03T15:00:00.000+07:00`
- The event payload sent to Google Calendar API explicitly sets `timeZone: "Asia/Bangkok"`.
- Prevents any UTC offset drift (no 08:00 UTC shifts).

---

## 10. Security Boundary

- **Renderer**:
  - Captures microphone audio via Web Audio API.
  - Runs local Silero VAD ONNX model.
  - Sends base64 audio to Main process.
  - Receives transcript and agent response.
- **Electron Main**:
  - Manages `GEMINI_API_KEY` in environment variables.
  - Encapsulates Google OAuth tokens, refresh tokens, and credentials.
  - Communicates with Google Calendar API.
  - Never exposes secrets over IPC or to `window.api`.

## 13. What is Intentionally NOT Implemented

As strictly mandated by Milestone 2.4 specifications:

- ❌ **TTS (Text-to-Speech)**: No voice playback of assistant answers (reserved for M3).
- ❌ **Wake Word**: No "Hey Assistant" hotword detection (reserved for M4).
- ❌ **Streaming STT**: Speech is processed per discrete segment after VAD speechEnd.
- ❌ **Streaming LLM Response**: Complete responses returned synchronously.
- ❌ **Conversation Memory / History Context**: Each voice request is evaluated as an independent command.
- ❌ **System Tray / Background Audio**: App runs in the standard desktop window.
- ❌ **Barge-in / Interruption**: TTS is not present, so audio ducking/interruption is not applicable.
