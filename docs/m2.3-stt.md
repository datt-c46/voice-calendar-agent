# Milestone 2.3: Speech-to-Text (STT)

## 1. STT Provider Selection & Rationale

For Milestone 2.3, the system introduces a pluggable Speech-to-Text abstraction (`ISpeechToTextProvider`) and configures two providers managed by `SpeechToTextManager`:

1. **Primary Cloud Provider — Google Gemini Multimodal Audio (`GeminiSpeechToTextProvider`)**:
   - Uses the official `@google/genai` SDK (`^2.24.0`, already included in `package.json`).
   - Model: `gemini-2.5-flash`.
   - **Why Selected**:
     - Pre-installed dependency; requires zero additional native or heavy machine learning packages.
     - State-of-the-art recognition accuracy for conversational Vietnamese diacritics and calendar terminology ("chiều mai lúc 3 giờ", "họp với A", "dời lịch").
     - Fast cloud inference with low token latency.
     - Operates strictly inside the Electron Main process with API key encapsulation.
2. **Deterministic Fallback Provider — `MockSpeechToTextProvider`**:
   - Provides instantaneous offline speech transcription for testing, local development, and environments where `GEMINI_API_KEY` is not yet configured.
   - Guarantees the desktop application starts and functions deterministically without network dependencies.

## 2. Architecture & Pipeline

The audio and transcription pipeline strictly preserves the required milestone boundaries:

```
[User Microphone]
       │
       ▼ (getUserMedia)
 [MediaStream]
       │
       ▼
 [AudioContext]
   ├──> [AnalyserNode] ───────> [Audio Level UI: 0..1 Bar & Meter] (M2.1)
   └──> [Silero VAD] (M2.2)
             │
             ├──> [onSpeechStart]  ──> Set state: 'speaking'
             └──> [onSpeechEnd]    ──> Float32Array (16kHz PCM)
                                             │
                                             ▼
                                    [WAV Audio Encoder] (16-bit Mono WAV Base64)
                                             │
                                             ▼ (IPC: 'stt:transcribe')
                                  [Electron Main Process]
                                             │
                                             ▼
                                [SpeechToTextManager]
                                             │
                                             ▼
                         [Gemini STT / Mock STT Provider]
                                             │
                                             ▼
                                       [STTResult]
                                             │
                                             ▼ (IPC response)
                                  [Renderer React UI]
                                             │
                                             ▼
                                [TranscriptionDisplay Card]
                                ("Ngày mai tôi có lịch gì?")
```

### Critical Architectural Boundary:

- **No Automatic Command Execution**: The recognized text is displayed in the UI (`TranscriptionDisplay`) and held in component state.
- **Do NOT Connect STT $\rightarrow$ Agent $\rightarrow$ Calendar yet**: Executing the transcribed text through the natural language intent extractor and Google Calendar CRUD is strictly reserved for **Milestone 2.4**.

## 3. Audio Format & Conversion

### 3.1. Raw Audio from VAD (M2.1 / M2.2)

- **Source**: `onSpeechEnd(audio: Float32Array)` from Silero VAD (`@ricky0123/vad-web`).
- **Sample Rate**: 16,000 Hz (16 kHz).
- **Channels**: 1 (Mono).
- **Sample Representation**: 32-bit Floating Point normalized in `[-1.0, 1.0]`.

### 3.2. Conversion Utility (`src/renderer/src/utils/audioEncoder.ts`)

- **Format**: Standard 16-bit PCM WAV.
- **Header**: 44-byte standard RIFF/WAVE header (AudioFormat: `1`, NumChannels: `1`, SampleRate: `16000`, ByteRate: `32000`, BlockAlign: `2`, BitsPerSample: `16`).
- **Encoding**: 32-bit float samples clamped and scaled to signed 16-bit integers (`sample * 0x7fff`).
- **Transfer**: Converted to Base64 via `arrayBufferToBase64()` for safe, low-overhead IPC transfer to the Main process.

## 4. STT Request Lifecycle & Buffering

The audio buffer follows a strictly bound, non-leaking lifecycle:

```
[IDLE]
  │
  ▼ User speaks
[SPEECH_START]  ──> VAD marks start timestamp
  │
  ▼ Speech continues
[RECORDING_BUFFER] (Float32Array frames accumulated by VAD)
  │
  ▼ User pauses (>400ms)
[SPEECH_END]    ──> Segment finalized, Float32Array emitted
  │
  ▼
[ENCODE_WAV]    ──> Converted to 16-bit PCM WAV Base64
  │
  ▼
[TRANSCRIBING]  ──> IPC invoke 'stt:transcribe' (latency timer running)
  │
  ▼
[RESULT / SUCCESS] ──> STTResult returned to UI, buffer immediately released
```

- **Memory Safety**: Neither raw PCM arrays nor base64 payloads are retained in memory after transcription completes.
- **No Disk Retention**: Zero audio files are persisted to disk.

## 5. STT State Machine

The React state machine transitions seamlessly:

- `'idle'`: Microphone and VAD inactive.
- `'listening'`: Microphone active, VAD listening, no speech detected.
- `'speaking'`: Voice activity detected, pulsing red indicator.
- `'transcribing'`: VAD finalized speech; STT request in flight to Gemini/Mock provider (`⏳ Transcribing audio...`).
- `'success'`: Transcription complete, text displayed in quotation card with latency pill.
- `'error'`: Handled error if network, provider, or empty audio segment fails.

## 8. Latency Measurement

- The hook tracks transcription turnaround time:
  $$\text{transcriptionLatencyMs} = T_{\text{response}} - T_{\text{requestStart}}$$
- Local/Mock latency: $< 5\text{ms}$.
- Gemini Cloud STT latency: typically $\sim 250\text{ms} - 650\text{ms}$ depending on network connection and audio length.
- Latency is recorded for developer diagnostics and rendered on the UI card.

---

## 9. Error Handling

- **Missing Audio / Empty Segment**: Throws descriptive `'No audio data provided for transcription.'` error; does not crash application.
- **Missing API Key**: Falls back automatically to `MockSpeechToTextProvider` with informative console notice.
- **Provider / Network Error**: Catches exception, sanitizes error message, transitions UI to `'error'` state with user-facing message.
- **Double-Recording Guard**: `isTranscribingRef` prevents concurrent overlapping STT requests if user begins speaking before previous transcription returns.

---

## 10. Security Considerations

- **Zero Secret Exposure**: `GEMINI_API_KEY` is loaded exclusively from `process.env` in the Electron Main process. It is **never** sent to the Renderer process or exposed on `window.api`.
- **Sanitized Errors**: Error logging redacts any query parameters matching `key=...` to prevent API key leaks in stdout/stderr.
- **Audio Privacy**: Audio is sent to the selected provider solely for transcription and discarded immediately. No audio is recorded to permanent storage.
