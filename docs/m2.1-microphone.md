# Milestone 2.1: Microphone + Audio Capture

## 1. Overview & Objective

Milestone 2.1 introduces audio capture capabilities for the Voice Calendar Agent desktop application. In this milestone:

- The user can start and stop microphone listening on demand via the user interface.
- Microphone audio is captured locally in the React Renderer process using standard Web Audio APIs.
- A real-time audio volume indicator displays the user's voice intensity.
- All previous functionality from Milestone 1 and Milestone 1.5 (Google Calendar OAuth 2.0, CRUD operations, Mock fallback, rule-based Vietnamese/English intent extraction, and `Asia/Bangkok` timezone normalization) is strictly preserved without modification.

---

## 2. Architectural Boundaries & Pipeline

In accordance with Milestone 2.1 specifications:

```
[Text Input] ──> [Rule-Based Extractor] ──> [DateTime Normalizer] ──> [Calendar Service]
                                                                              │
                                                                   (Google Calendar / Mock)

[Microphone Hardware]
       │
       ▼ (getUserMedia)
 [MediaStream]
       │
       ▼ (createMediaStreamSource)
 [AudioContext]
       │
       ▼
 [AnalyserNode] ──> [Real-time Audio Level Calculation] ──> [React UI Level Bar & Text Meter]
```

### Critical Boundaries:

- **No IPC for Raw Audio**: Audio streams and raw PCM frames remain strictly in the Renderer process. They are not transmitted across the Electron IPC bridge.
- **No VAD / STT / TTS**: Voice Activity Detection (Silero/Web Audio VAD), Speech-to-Text (Whisper), Text-to-Speech, Wake Word, and Gemini audio streaming are deferred to subsequent milestones (M2.2, M2.3, etc.).
- **Zero Audio Persistence**: Audio is neither recorded to disk nor uploaded to any remote or cloud server.

## 3. Implementation Details

### 3.1. Renderer Audio Hook (`useMicrophone.ts`)

Located at: `src/renderer/src/hooks/useMicrophone.ts`

- **Exposed API**:
  - `status`: `'idle' | 'requesting' | 'listening' | 'stopped' | 'error'`
  - `start()`: Asynchronous method to request permission and initialize Web Audio nodes.
  - `stop()`: Synchronous method to halt capture, release hardware tracks, and close the audio context.
  - `audioLevel`: Normalized floating point value between `0.0` (silence) and `1.0` (peak speaking level).
  - `error`: User-friendly Vietnamese/English error message if access is denied or hardware fails.
- **Web Audio Implementation**:
  - Employs `navigator.mediaDevices.getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true } })`.
  - Connects `MediaStreamAudioSourceNode` to an `AnalyserNode` (`fftSize = 256`, `smoothingTimeConstant = 0.4`).
  - Utilizes `requestAnimationFrame` to sample frequency bins via `analyser.getByteFrequencyData()`, computing a responsive, normalized volume level.

### 3.2. User Interface Component (`MicrophoneControl.tsx`)

Located at: `src/renderer/src/components/MicrophoneControl.tsx`

- **State Badges & Labels**:
  - `Microphone: Ready` (Gray badge)
  - `Microphone: Requesting...` (Amber badge)
  - `Microphone: Listening` (Green badge)
  - `Microphone: Stopped` (Gray badge)
  - `Microphone: Permission denied` (Rose badge)
  - `Microphone: Error` (Rose badge)
- **Interactive Controls**:
  - `[ 🎙 Start Listening ]` button when idle or stopped.
  - `[ 🔴 Stop Listening ]` button when actively capturing.
- **Visual Metering**:
  - Terminal-style segment meter: `[████████──]` (10 steps).
  - Smooth progress bar track with color thresholds (Green for normal speech, Amber for elevated, Rose for near-clipping).
  - Numerical percentage readout (`0%` - `100%`).
  - Graceful error banner display for hardware or permission faults.

### 3.3. Electron Main Process Permission Handling (`src/main/index.ts`)

- Configured granular permission checks using Electron session handlers:
  - `session.defaultSession.setPermissionRequestHandler`: Specifically inspects `permission === 'media'` and grants access exclusively when `mediaTypes` contains only `'audio'`. Arbitrary or video requests are rejected.
  - `session.defaultSession.setPermissionCheckHandler`: Restricts media checks to `details.mediaType === 'audio'`.
- Preserves full Electron security standards (`contextIsolation: true`, `nodeIntegration: false`, `sandbox: false` with preload barrier).

## 4. Resource Cleanup Behavior

To prevent memory leaks and hardware lockups:

1. **Manual Stop**:
   - Cancels the active `requestAnimationFrame` loop.
   - Disconnects `MediaStreamAudioSourceNode` and `AnalyserNode`.
   - Calls `.stop()` on every `MediaStreamTrack` to immediately extinguish the hardware microphone indicator LED.
   - Calls `.close()` on `AudioContext`.
   - Resets `audioLevel` to `0`.
2. **Component Unmount**:
   - The `useEffect` cleanup hook in `useMicrophone` triggers `cleanupResources()`, guaranteeing that navigating away or closing views releases the microphone immediately.
3. **Double-Call Guards**:
   - Calling `start()` while already `listening` or `requesting` is a no-op.
   - Calling `stop()` while already `stopped` or `idle` is a no-op.

## 5. Error Handling

The hook catches and categorizes browser/hardware exceptions:

- `NotAllowedError` / `PermissionDeniedError`: Displays `"Quyền truy cập Microphone bị từ chối (Permission denied)."`.
- `NotFoundError` / `DevicesNotFoundError`: Displays `"Không tìm thấy thiết bị Microphone (No microphone found)."`.
- `NotReadableError` / `TrackStartError`: Displays `"Microphone đang được sử dụng bởi ứng dụng khác."`.
- Generic / Context errors: Displays descriptive message without crashing Electron.

## 7. Known Limitations (By Design for M2.1)

- **Visual Meter Only**: Captures audio solely to display volume intensity; spoken audio is not yet converted to text.
- **No VAD (Voice Activity Detection)**: The microphone stays open until the user clicks "Stop Listening" (VAD is slated for Milestone 2.2).
- **No Audio Transmission**: Audio frames are discarded after computing RMS/frequency energy.
