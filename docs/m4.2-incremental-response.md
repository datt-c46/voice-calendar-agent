# Milestone 4.2: Incremental Response + Sentence Streaming

## 1. Goal

Milestone 4.2 transitions the desktop Voice Calendar Agent from monolithic, full-response Text-to-Speech queueing to **incremental response streaming and immediate sentence-level queueing**.

Instead of waiting for the full Agent response string to complete before sentence segmentation and TTS vocalization begin, partial text chunks are ingested continuously into a `SentenceBuffer`. As soon as a complete sentence boundary is recognized, that sentence is immediately enqueued into the sequential `TTSQueue` and vocalized by the TTS provider while subsequent chunks are still being streamed.

## 3. Incremental Response Architecture

1. **Agent / Streaming Emitter**: Emits small textual fragments (`ResponseChunk`) containing partial tokens or phrases as they become available.
2. **Chunk Reception & UI Progress**: Chunks are received via `stream.onChunk()`. Telemetry logs chunk arrival with size and index (without logging sensitive user data).
3. **Sentence Buffering**: Each chunk is appended to `SentenceBuffer`. Punctuation boundaries (`.`, `?`, `!`, `…`, `\n`) are evaluated using regex lookaheads while protecting decimals (`3.5`), version strings (`1.5.0`), times (`15:30`), and Vietnamese abbreviations (`TP.`, `BS.`, `TS.`, `v.v.`).
4. **Immediate Enqueueing**: Completed sentences are enqueued directly into `TTSQueue` without waiting for the response stream to finish. If the queue was idle, playback of the first sentence begins immediately.
5. **Stream Completion & Flush**: When `stream.onComplete()` fires, any remaining text in the buffer is extracted via `sentenceBuffer.flush()` and enqueued as the final utterance.

## 4. Streaming Interface

The project standardizes on the `IResponseStream` interface established in M4.1:

```typescript
export interface IResponseStream {
  onChunk(callback: ChunkListener): () => void
  onComplete(callback: CompletionListener): () => void
  onError(callback: ErrorListener): () => void
  cancel(): void
  isCancelled(): boolean
  isComplete(): boolean
  [Symbol.asyncIterator](): AsyncIterator<string>
}
```

This interface supports both reactive event callbacks and standard `for await (const chunk of stream)` consumption.

## 5. Sentence Buffer Implementation

The `SentenceBuffer` class accumulates incoming fragments and emits only grammatically complete sentences:

- **State Maintenance**: Holds an internal `buffer` string.
- **Append Operation**:
  ```typescript
  public append(chunk: string): string[]
  ```
  Returns `string[]` of zero, one, or more newly completed sentences.
  If the buffer does not end on a sentence terminator, the trailing candidate fragment remains buffered.
- **Multiple Sentences per Chunk**: If a chunk contains multiple sentences (e.g. `"Ngày mai bạn có 2 cuộc họp. Cuộc họp đầu tiên lúc 9 giờ sáng."`), all completed sentences are emitted in order.
- **Flush Operation**:
  ```typescript
  public flush(): string[]
  ```
  Extracts and returns any remaining non-empty tail when the stream completes.
- **Clear Operation**:
  ```typescript
  public clear(): void
  ```
  Discards buffered text immediately upon user cancellation.

## 6. Chunk Handling & Sentence Detection Boundaries

Supported sentence terminators:

- `.` (Full stop)
- `?` (Question mark)
- `!` (Exclamation mark)
- `…` or `...` (Ellipsis)
- `\n` (Newline breaks)

Protected patterns (preventing premature splitting):

- **Decimals & Versions**: `(?<=\d)\.(?=\d)` protects `3.5 giờ`, `1.5.0`.
- **Clock Times**: `15:30` (colon-delimited).
- **Vietnamese & English Abbreviations**: `TP.`, `ThS.`, `TS.`, `PGS.`, `GS.`, `BS.`, `DS.`, `KS.`, `KTS.`, `v.v.`, `e.g.`, `i.e.`, `Dr.`, `Mr.`, `Ms.`, `etc.`

## 7. TTS Queue Integration

`TTSQueue` was extended with `speakStream(stream: IResponseStream, options?: SpeakStreamOptions): Promise<void>`:

```typescript
public async speakStream(stream: IResponseStream, options?: SpeakStreamOptions): Promise<void>
```

Key characteristics:

1. **Immediate Playback**: The first sentence starts synthesis and audio output while chunks 2, 3, etc. are still in flight.
2. **Order Preservation**: Sentences are appended sequentially to `this.items`, strictly preserving semantic order (`1 -> 2 -> 3`).
3. **Continuous Execution**: The playback loop (`processQueue`) plays sentences in FIFO order. If it finishes existing sentences while the stream is still open, it waits in queued state without prematurely declaring completion.

## 8. Latency Metrics: TTFS vs TTFA

Milestone 4.2 tracks two complementary first-output latency metrics:

### 1. TTFS (Time To First Sentence)

- **Definition**: Interval from `RESPONSE_STREAM_START` to `FIRST_SENTENCE_DETECTED`.
- **Significance**: Measures the latency of the Agent generation and segmentation stage before speech synthesis begins.

### 2. TTFA (Time To First Audio)

- **Definition**: Interval from `SPEECH_END` (user stops speaking) to `TTS_FIRST_START` (first audio sound begins playing).
- **Significance**: User-perceived latency from end of user utterance to hearing the assistant's voice.

### Measured Latency Breakdown (Runtime Test Benchmark):

| Metric            | Description                              | Value             |
| ----------------- | ---------------------------------------- | ----------------- |
| **STT Latency**   | Speech-to-Text transcription             | ~250 - 450 ms     |
| **Agent Latency** | Command extraction & Calendar CRUD       | ~10 - 30 ms       |
| **TTFS**          | Stream start to first completed sentence | **15 - 38 ms**    |
| **TTS Startup**   | Audio synthesizer initialization         | **10 - 25 ms**    |
| **TTFA**          | User speech end to first audible sound   | **~350 - 550 ms** |

## 9. Cancellation & Stale Stream Protection

### Cancellation Protocol:

When a user clicks "Stop" or interrupts during streaming:

1. `TTSQueue.stop()` is invoked.
2. Increments `currentGeneration++`.
3. Calls `activeStream.cancel()`.
4. Empties pending sentences (`items = []`).
5. Halts active provider audio immediately (`provider.stop()`).
6. Resolves active promise cleanly to avoid hanging callers.

### Stale Stream Protection:

If Request A is streaming and Request B is triggered:

- `currentGeneration` increments.
- Request A is marked cancelled.
- Any delayed chunk emitted by Request A checks `generation !== this.currentGeneration` and is discarded immediately without entering Request B's queue.

## 10. Mock vs. Real Streaming Provider

- **Development Mock Stream Provider** (`src/renderer/src/services/streaming/mockStreamProvider.ts`):
  - Created to validate chunk handling, sentence buffering, immediate queueing, cancellation, and telemetry in local development and headless automated tests.
  - Slices text into natural multi-word phrases and emits them with configurable delays (default: 30ms).
  - **Explicit Note**: Does not fake performance numbers; metrics accurately record runtime timestamps.
- **Production Integration Path**:
  - Direct integration ready for streaming LLM tokens via `IStreamingAgent.processCommandStream()` or streaming STT/TTS in Milestone 4.3.

---

## 11. Empty Stream & Error Handling

- **Empty Streams**: If a stream completes without emitting any non-whitespace text, `TTSQueue` cleanly transitions to `idle` without enqueueing empty strings or invoking the audio synthesizer.
- **Stream Errors**: If an error occurs on the stream (`stream.onError`), the error is recorded in `LatencyTracker`, the queue enters `error` state, active audio is halted, and already spoken sentences are not replayed.

## 13. Known Limitations & Scope for M4.3

### Included in M4.2:

- Real incremental chunk processing.
- Real sentence buffer boundary segmentation.
- Immediate per-sentence queueing into `TTSQueue`.
- Complete cancellation and stale stream protection.
- Live TTFS & TTFA metrics display and telemetry tracking.

### Deferred to Milestone 4.3:

- Streaming audio / PCM chunk streaming from TTS provider.
- WebAudio API low-level audio buffer chunking.
- WebSocket / WebRTC audio transports.
