# Milestone 2.2: Voice Activity Detection (VAD)

## 1. Overview & Goal

Milestone 2.2 incorporates real-time Voice Activity Detection (VAD) into the existing Electron + React desktop application, operating entirely on-device within the Renderer process.

The application detects four distinct speech states:

1. **No speech** (Silence / Ambient background)
2. **Speech started** (`onSpeechStart` — user starts speaking)
3. **User is speaking** (`speaking` state — live voice activity)
4. **Speech ended** (`onSpeechEnd` — user finishes an utterance)

All previously completed capabilities (Milestone 1 Text-to-Calendar MVP, Milestone 1.5 Real Google Calendar OAuth 2.0 & CRUD with `Asia/Bangkok` timezone normalization, and Milestone 2.1 Web Audio capture & level metering) remain 100% operational and regression-free.

---

## 2. Library & Dependencies

- **VAD Library**: `@ricky0123/vad-web` (version `^0.0.31`)
- **ONNX Inference Runtime**: `onnxruntime-web` (version `^1.30.0`)
- **Model**: Silero VAD (legacy v4 ONNX model `silero_vad_legacy.onnx` and v5 `silero_vad_v5.onnx`)
- **Execution Target**: Browser/Renderer process using WebAssembly (`wasmPaths: './vad/'`) and local ONNX files.
- **No Extra Libraries**: Zero additional VAD or audio dependencies were introduced.

---

## 3. Architecture & Audio Flow

The VAD subsystem is situated solely in the Renderer process. Neither raw audio chunks nor ONNX tensors are routed across the Electron IPC barrier.

```
[User Microphone]
       │
       ▼ (getUserMedia)
 [MediaStream]
       │
       ▼
 [AudioContext]
   ├──> [AnalyserNode] ───────> [Audio Level UI: 0..1 Bar & Meter] (M2.1)
   └──> [Silero VAD (MicVAD)]
             │
             ├──> [onSpeechStart]  ──> Set state: 'speaking' (🔴 Speaking...)
             ├──> [onSpeechEnd]    ──> Set state: 'speech-ended' (✓ Speech detected)
             └──> [onVADMisfire]   ──> Revert state: 'listening' (No speech detected)
```

### Strict Architectural Boundaries:

- **No VAD $\rightarrow$ STT Yet**: When `onSpeechEnd` triggers, speech metadata (duration, sample length, timestamp) is recorded and displayed locally. No speech-to-text conversion (Whisper or cloud STT) is performed; STT is strictly reserved for Milestone 2.3.
- **Stream Reuse**: Exactly one `MediaStream` and one `AudioContext` are initialized per listening session. `useVoiceActivity` seamlessly consumes the audio stream and AudioContext created by `useMicrophone`.
- **Zero Audio Persistence**: Audio is neither saved to disk nor streamed to Gemini, Google, OpenAI, or external endpoints.

## 4. State Machine & Event Handling

### 4.1. VAD States

The hook exposes a strongly-typed `vadState`:

- `'idle'`: Microphone and VAD are inactive.
- `'initializing'`: Requesting microphone access, initializing AudioContext, loading Silero ONNX model and WASM runtime.
- `'listening'`: VAD active and monitoring audio frames; ambient background noise only.
- `'speaking'`: Silero model probability exceeds positive speech threshold; user is currently speaking.
- `'speech-ended'`: Speech segment finished; silence threshold observed for the redemption period.
- `'error'`: Handled permission denial, missing hardware, or model initialization failure.

### 4.2. Event Handlers

- **`onSpeechStart`**:
  - Sets `vadState = 'speaking'` and `isSpeechDetected = true`.
  - Records speech start timestamp (`speechStartTimestampRef`).
  - Clears any pending grace period transition timers.
  - UI displays pulsing red indicator (`🔴 Speaking...`).
- **`onSpeechEnd(audio: Float32Array)`**:
  - Sets `vadState = 'speech-ended'` and `isSpeechDetected = false`.
  - Increments `speechCount` by 1.
  - Records `lastSpeechInfo` (`durationMs`, `timestamp`, `samples`).
  - Sets a 2.5-second reset timer to smoothly return to `'listening'` if the user pauses before another utterance.
- **`onVADMisfire`**:
  - Triggered if an energy burst began but was shorter than `minSpeechMs` (250ms).
  - Cleanly reverts `vadState` to `'listening'` and resets `isSpeechDetected = false`.
  - Transient noise, key clicks, or coughs do not register as spoken commands.

## 5. Configuration & Thresholds

Configuration parameters adhere to Silero VAD standards:

- **`positiveSpeechThreshold: 0.5`**: Probability above 0.5 confirms positive voice activity.
- **`negativeSpeechThreshold: 0.35`**: Probability below 0.35 confirms silence (0.15 hysteresis prevents flutter).
- **`redemptionMs: 400`**: 400ms pause tolerance between words prevents cutting off compound sentences.
- **`minSpeechMs: 250`**: Audio bursts shorter than 250ms are classified as misfires and filtered out.
- **`preSpeechPadMs: 400`**: 400ms leading audio prepended to speech segment for natural onset capture.
- **`processorType: 'auto'` with fallback to `'ScriptProcessor'`**: Attempts `AudioWorklet` first; gracefully falls back to `ScriptProcessor` if worklet instantiation is constrained.

---

## 6. Resource Cleanup & Lifecycle

1. **Manual Stop**:
   - Destroys active `MicVAD` instance (`await vad.destroy()`).
   - Stops all `MediaStreamTrack`s, turning off the physical microphone indicator.
   - Closes the `AudioContext`.
   - Clears pending `setTimeout` and `requestAnimationFrame` timers.
   - Resets state to `'idle'`.
2. **Component Unmount**:
   - The `useEffect` return handler invokes `destroyVad()`, ensuring no detached audio worklets, WASM instances, or media tracks persist when unmounting.
3. **Repeated Sessions**:
   - Start $\rightarrow$ speak $\rightarrow$ stop can be executed indefinitely without accumulating memory or open audio handles.

## 8. Known Limitations (By Design for M2.2)

- **No STT**: VAD classifies when speech occurs, but does not transcribe spoken words to text yet (Milestone 2.3).
- **No Command Execution from Speech**: Commands are still entered via the text input field; voice-driven intent extraction will follow once STT is integrated.
