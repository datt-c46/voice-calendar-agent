# Milestone 4.1: Streaming Architecture + Latency Instrumentation

## 1. Goal & Architecture Overview

Milestone 4.1 establishes the architectural foundation and fine-grained latency telemetry needed for streaming audio interactions. It measures the complete voice pipeline, identifies operational bottlenecks, and introduces streaming-ready abstractions (**SentenceBuffer**, **IResponseStream**, **IStreamingAgent**, **Backpressure guards**) without yet connecting live streaming audio chunking or LLM token streaming.

### Current Non-Streaming Architecture (M3.2 / M4.1 baseline):

```
Agent
  ↓
Full Response
  ↓
Formatter
  ↓
Sentence Splitter
  ↓
TTS Queue
  ↓
Speaker
```

### Target Streaming Architecture (M4.2 Preparation):

```
Agent Stream (Tokens / Incremental Chunks)
  ↓
Sentence Buffer (Token Accumulator & Sentence Boundary Detector)
  ↓
TTS Queue (FIFO Sequential Synthesis & Playback)
  ↓
Speaker
```

---

## 2. Why Streaming is Needed

In the monolithic (non-streaming) pipeline:

1. **Full Turn Latency**: The user must wait for:
   $$\text{TTFA} = t_{\text{SpeechEnd}} \to t_{\text{STT Complete}} \to t_{\text{Agent Complete}} \to t_{\text{Format Complete}} \to t_{\text{TTS Start}}$$
   If the Agent processes a complex LLM query taking 1.5–3.0 seconds, the user experiences dead silence.
2. **Audio Playback Starvation**: TTS synthesis cannot begin until the entire response text has been completely generated by the Agent.
3. **Bandwidth & Compute Peaks**: Processing responses in large monolithic blocks produces compute spikes rather than smooth pipelined execution.

Streaming addresses this by enabling synthesis of sentence 1 as soon as sentence 1 is detected, while sentences 2 and 3 are still being generated by the Agent.

---

## 3. Telemetry Architecture

Telemetry is implemented via high-resolution monotonic timers (`performance.now()`) paired with wall-clock epoch timestamps (`Date.now()`). The tracker operates in both Electron Renderer (`src/renderer/src/services/telemetry/`) and Node.js Main process (`src/main/telemetry/`).

### Stage Pipeline Events:

```
[USER SPEECH]
      │
      ▼
SPEECH_START           (User voice begins triggering VAD)
      │
      ▼
SPEECH_END             (VAD detects end of speech segment)
      │
      ▼
STT_START              (Audio payload dispatched to STT engine)
      │
      ▼
STT_FIRST_RESULT       (Initial transcript token or preview)
      │
      ▼
STT_COMPLETE           (Final recognized text with language detection)
      │
      ▼
AGENT_START            (Command forwarded to Agent Orchestrator)
      │
      ▼
AGENT_COMPLETE         (Intent classification & Calendar CRUD complete)
      │
      ▼
RESPONSE_FORMAT_START  (Conversion into visual UI & conversational text)
      │
      ▼
RESPONSE_FORMAT_COMPLETE
      │
      ▼
TTS_QUEUE_START        (Sentences enqueued to FIFO TTS Queue)
      │
      ▼
TTS_FIRST_START        (First audio utterance begins playback -> TTFA)
      │
      ▼
TTS_COMPLETE           (All sentences finished playback)
```

---

## 4. Interaction Session ID

Every voice interaction is assigned a unique UUID v4 generated at `SPEECH_START` (e.g. `5ca98269-xxxx-4xxx-yxxx-xxxxxxxxxxxx`).

- All stage events and telemetry logs share this `interactionId`.
- Prevents cross-talk or mixing metrics when sequential or preemptive commands occur.
- No personal user data or calendar entries are stored in the session ID.

## 5. Latency Metrics Model

```typescript
export interface LatencyMetrics {
  interactionId: string
  speechDurationMs: number // speechEnd - speechStart
  sttLatencyMs: number // sttComplete - sttStart
  agentLatencyMs: number // agentComplete - agentStart
  responseFormatLatencyMs: number // formatComplete - formatStart
  ttsQueueLatencyMs: number // ttsComplete - ttsQueueStart
  ttsStartupLatencyMs: number // ttsFirstStart - ttsQueueStart
  speechEndToSttStartMs: number // sttStart - speechEnd
  speechEndToTranscriptMs: number // sttComplete - speechEnd
  speechEndToAgentCompleteMs: number // agentComplete - speechEnd
  timeToFirstAudioMs: number // TTFA = ttsFirstStart - speechEnd
  totalFromSpeechEndMs: number // ttsComplete - speechEnd
  totalDurationMs: number // ttsComplete - speechStart
}
```

## 6. Time To First Audio (TTFA)

**TTFA** is defined as the elapsed duration from the moment the user stops speaking (`SPEECH_END`) until the assistant's first audio utterance begins playing on the speaker (`TTS_FIRST_START`):

$$\text{TTFA} = t_{\text{TTS\_FIRST\_START}} - t_{\text{SPEECH\_END}}$$

In the current baseline, TTFA includes:
$$\text{TTFA} = \Delta t_{\text{VAD to STT}} + \Delta t_{\text{STT}} + \Delta t_{\text{Agent}} + \Delta t_{\text{Formatting}} + \Delta t_{\text{TTS Queue Startup}}$$

## 7. Sentence Buffer (`SentenceBuffer.ts`)

The `SentenceBuffer` is designed to ingest partial streaming tokens and emit clean, discrete sentences without prematurely splitting on decimals, time formats, abbreviations, or ellipsis:

```typescript
export class SentenceBuffer {
  append(chunk: string): string[]
  flush(): string[]
  clear(): void
  getRemaining(): string
  isEmpty(): boolean
}
```

### Demonstrated Execution:

- Chunk 1: `"Ngày mai bạn có"` -> Buffer: `"Ngày mai bạn có"`, Emits: `[]`
- Chunk 2: `" 2 cuộc họp."` -> Buffer: `""`, Emits: `["Ngày mai bạn có 2 cuộc họp."]`
- Chunk 3: `"Cuộc họp đầu tiên"` -> Buffer: `"Cuộc họp đầu tiên"`, Emits: `[]`
- Chunk 4: `" lúc 9 giờ sáng."` -> Buffer: `""`, Emits: `["Cuộc họp đầu tiên lúc 9 giờ sáng."]`
- Chunk 5: `"Dự kiến kéo dài 3."` -> Protected decimal dot; Emits: `[]`
- Chunk 6: `"5 giờ."` -> Emits: `["Dự kiến kéo dài 3.5 giờ."]`

## 8. Streaming-Ready Interfaces

Defined in `src/renderer/src/services/streaming/types.ts`:

- **`IResponseStream`**: Supports chunk callbacks (`onChunk`), completion notifications (`onComplete`), errors (`onError`), cancellation (`cancel`), and standard `AsyncIterable<string>` (`for await (const chunk of stream)`).
- **`IStreamingAgent`**: Prepared contract for streaming LLM orchestrators:
  ```typescript
  export interface IStreamingAgent {
    processCommandStream(command: string): Promise<IResponseStream>
  }
  ```
- **`SimpleResponseStream`**: Concrete implementation supporting synchronous or asynchronous chunk emission and async iteration.

---

## 9. Backpressure Considerations

When response generation speed exceeds TTS playback speed:

- Text tokens can accumulate rapidly in memory.
- `TTSQueue` is bounded with configurable thresholds:
  - `maxQueueSize`: 50 sentences (enqueue drops or delays to protect memory).
  - `highWaterMark`: 30 sentences (emits backpressure warning signals).
  - `isOverloaded()`: reports overload state to throttle the generator.

---

## 10. Cancellation Architecture

When a cancellation occurs (user clicks stop or speaks a new command):

1. Telemetry records `CANCELLED` with reason and active `interactionId`.
2. `SentenceBuffer.clear()` discards any partial token chunks immediately.
3. `SimpleResponseStream.cancel()` halts chunk propagation and closes async iterators.
4. `TTSQueue.stop()` increments the generation token, flushes queued sentences, and terminates speech playback immediately.

## 12. Observed Bottlenecks

1. **Monolithic STT Barrier**:
   The entire audio file (e.g. 1.5–2.2 seconds of speech) must be recorded, WAV-encoded in base64, and transmitted over IPC before STT transcription begins.
2. **Serial Agent Execution**:
   Intent extraction and calendar lookup execute only after the entire transcript is returned.
3. **Monolithic Response Handover**:
   The entire assistant response message is generated before sentence segmentation and TTS queue synthesis start.
4. **Target for M4.2 Optimization**:
   With `SentenceBuffer` and incremental response streaming, TTFA will only depend on the time to produce the **first sentence**, cutting user-perceived latency significantly.

---

## 13. What is Deferred to M4.2

To preserve clean milestone boundaries, the following are intentionally deferred to M4.2:

- ❌ **Live LLM Token Streaming**: Connecting OpenAI/Gemini streaming response APIs.
- ❌ **Streaming Audio Chunks**: Web Audio PCM streaming, WebSocket/WebRTC transports.
- ❌ **Streaming STT**: Chunk-based speech recognition.
- ❌ **Barge-in / Voice Interruption during Assistant Speech**: Microphone gating remains active with acoustic feedback cooldown.
